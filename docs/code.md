# コードを動かす

本家の `guide/member/03-code.ja.md`・`10-integrations.ja.md` から、コミット・データベース・
動かしたアプリの確認を抜き出した。

## コミットと push

リポジトリの行を右クリックして「コミットグラフを開く」で、ブランチのグラフと選んだコミットの
差分が開く。ヘッダの「変更」で変更ファイルの一覧を開き、ファイルごとに stage して、
コミットメッセージを書いて「Commit」を押す。ヘッダには fetch（`git fetch --prune`）と
Fast-Forward（`pull --ff-only`）のボタンもある。

push は端末かエージェントから `git push` で行う。GitHub に接続してあれば認証は自動で通る。

リポジトリと worktree の行には、push の前に見ておく状態が出る。

| 表示 | 意味 |
|---|---|
| 未コミット | コミットしていない変更がある |
| ↑N | origin より N コミット進んでいる（未 push） |
| ↓N FF可 | origin が N コミット進んでいて、fast-forward できる |
| ↑N ↓N 要マージ | origin と分岐している |
| 未取込 N | worktree に、親にまだ入っていないコミットが N 件ある |
| 親+N・FF可 | 親が N コミット進んでいる。右クリックの「Fast-Forward で取り込む」で取り込める |

worktree の「親」は、親の作業コピーにあるブランチの upstream（`origin/main` など）である。
squash merge したブランチは、GitHub でマージ済みでも取り込み済みと表示されないことがある。

## データベースを使う

ワークスペースの中では、Docker を使わずに `af-db` で PostgreSQL と MySQL 8.4 を立てられる。
初回はダウンロードと初期化で数分かかる。

```bash
eval "$(af-db env)"          # PostgreSQL を立て、DATABASE_URL を入れる
af-db up mysql               # MySQL 8.4
eval "$(af-db env mysql)"    # AF_DB_URL_MYSQL と DATABASE_URL を入れる
af-db status                 # 稼働状況とポート
af-db down                   # 止める
```

- データベースは作業コピーごとに1つで、同じ作業コピーのセッションは同じものを共有する
- ポートは PostgreSQL が 5432、MySQL が 3306 で固定である。接続文字列を書き換えなくてよい
- データはホーム（`~/.local/state/af-db`）にあり、ワークスペースを止めても残る
- `psql` と `mysql` は PATH にあり、エンジンを起動したあとに開いたセッションなら引数なしで繋がる
- MySQL はアイドルでも 226 MB ほど常駐する。メモリを多く使うビルドの前に `af-db down mysql` で止める
- JDBC は unix socket に繋がらないので、`af-db url --tcp` で TCP の URL を使う。
  `go-sql-driver/mysql` 形式が要るときは `af-db url mysql --format=go-dsn`

⚙設定 →「データベース」タブでも、端末を開かずに起動・停止と状態の確認ができる。

## 動かしたアプリを開く

ワークスペースの中で dev サーバーを `127.0.0.1` か全インターフェースで listen させ、
ワークスペース操作バーのポート入力欄にポート番号を入れる。開き方は3つある。

| 開き方 | 向いている用途 |
|---|---|
| ペインで開く | 画面を触って確かめる。HMR・WebSocket・cookie・リダイレクトがそのまま動く |
| 軽量プレビュー | HTTP の応答を一度見る。URL がサブパスになるので、絶対パスを使うアプリは崩れる |
| プレビュー用サブドメイン | アプリをルート直下で開く。複数ポートを同時に開け、人にも見せられる |

プレビュー用サブドメインは、操作バーの「プレビュー」にポートごとの URL として並ぶ。
URL はワークスペースを起動するたびに変わり、既定ではログインが必要である。開けるポートは
⚙設定 →「プレビュー用サブドメイン」で決める（既定は 3000 と 8080）。

アプリ側では次の点に気をつける。

- フロントから API を `http://localhost:8080` と直書きで呼ばない。ブラウザから見た `localhost` は
  画面を見ている人の PC である。Vite の `server.proxy` や Next.js の `rewrites()` で `/api` を
  8080 へ流す
- proxy の転送先は `http://127.0.0.1:8080` のままにする。プレビューの URL に書き換えると、
  API が全部 401（`preview requires sign-in`）になる
- Next.js は `allowedDevOrigins` にプレビュー用ドメインをワイルドカードで足す。足さないと
  レイアウトの枠だけ出てデータが出ない
- Spring Boot は `server.forward-headers-strategy=framework` を設定する
- 自分の公開 URL を要するアプリには、コンテナ内の `AF_PREVIEW_URL_<ポート>` を渡す

同じテナントの同僚に見せるときは、⚙設定 →「プレビュー用サブドメイン」の「同じテナントの
メンバーに見せる」をオンにし、「共有」ボタンでコピーしたリンクを渡す。このリンクは再起動を
またいでも有効である。オンの設定は再起動しても戻らないので、見せ終わったら自分でオフにする。
相手が開いている間はワークスペースが自動停止しない。

ブラウザペインは1ワークスペースにつき同時に2つまでである。localhost 専用で、外部の URL は
開けない。
