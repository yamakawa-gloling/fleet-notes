# Docker 前提のリポジトリを Fleet で立てる

ローカル開発を `docker compose` 前提で組んだリポジトリを、Docker の無い Fleet のワークスペースで
立ち上げて画面まで開くための試し方を置く。まだ通していない計画であり、試した結果で書き直す。

## 前提

リポジトリの側に、Docker を使わない立て方が用意されていることを前提にする。具体的には次の2つである。

- DB を作り直すスクリプトなどが、接続先の MySQL を環境変数（ホスト・ポート・管理ユーザー）で受け取れる
- 画面の dev サーバーのポートを環境変数で変えられる

用意が無ければ、先にリポジトリの側でそれを作る。Fleet の側だけでは解決しない。

## 置き換え

| compose のサービス | Fleet での置き換え | 確かめること |
|---|---|---|
| MySQL 8.4 | `af-db up mysql`（ポートは 3306 で固定） | 管理ユーザーとパスワード（`af-db url mysql --tcp`）。トリガを作る権限が足りるか |
| S3 互換のストレージ | 用意しない | S3 を使う機能だけが動かないこと |
| 帳票などの Python のプロセス | 仮想環境（`uv venv`）に依存を入れて直接起動する | `uv` が無ければ `pip install --user uv`。pango と日本語フォントはイメージに入っている |
| API・画面 | ワークスペースの中で直接起動する | 下の「画面を開く」 |

MySQL のトリガは、SUPER 権限か `log_bin_trust_function_creators=1` が無いと作れない。compose では
MySQL の起動引数で後者を満たしていることが多い。af-db の管理ユーザーで足りなければ、
`SET GLOBAL log_bin_trust_function_creators = 1` を先に流す。

`/tmp` が実行不可の環境では、`go run`・`go test` が `permission denied` で落ちる。そのときは
`GOTMPDIR` に実行できるディレクトリを渡す。

## 画面を開く

開き方は `docs/code.md`「動かしたアプリを開く」にある。触って確かめるなら「ペインで開く」を使う。

- Vite は既定で `localhost` に listen し、IPv6 の `::1` だけで待つことがある。ペインで開けなければ
  `--host 127.0.0.1` を付けて起動する
- プレビュー用サブドメインで開くと、Vite が知らないホスト名を断ることがある（`server.allowedHosts`）
- `/api` の中継先は `http://127.0.0.1:8080` のままにする（`docs/code.md`）

## エージェントへの頼み方

リポジトリを clone した作業コピーでセッションを起動し、次のように頼む。直さずに止めさせるのは、
詰まった箇所を手順の誤りとして直すか、リポジトリの変更として扱うかを、結果を見てから決めるためである。

> README の「Docker を使わない立て方」を、このワークスペースで上から試してほしい。MySQL は
> `af-db up mysql` で立て、S3 は用意しない。詰まったところと、手順の書き方を直すべきところを
> 一覧にして、コードやファイルは直さずに止まって。最後に画面をペインで開けるかも確かめて。

確かめる項目は次のとおりである。

- DB を作り直すスクリプトが、af-db の MySQL に対して通る
- DB を使うテストが、skip 0 本で全通過する
- 帳票のプロセスが起動し、API 経由で PDF が返る
- 画面をペインで開き、`/api` の中継が通る
