# 使い始める

本家の利用ガイド（`guide/member/`）から、ログインから一日の終わりまでを抜き出した。
画面と食い違ったら画面が正しい。ガイドの全文は、ワークスペースが動いていれば Console の
アカウントメニュー「利用ガイド」から開ける。

## 最初に一度だけやること

接続先の URL とアカウントは、デプロイメントの管理者から受け取る。ブラウザがあればよい。

1. ログインする。画面最上部にテナント選択が出たら、作業するテナントを選ぶ
2. ようこそカードの「起動」でワークスペースを立ち上げる。「稼働中」になるまで、エージェントの
   接続を含めて他の操作はできない
3. ようこそカードの「接続する」でエージェントにサインインする。Claude は「OAuth 接続」で開いた
   タブで承認し、表示されたコードを貼って「完了」を押す。⚙設定 →「エージェント」タブに
   メールとプランが出れば接続済みである
4. ⚙設定 →「Gitホスティング」タブで GitHub に接続する。「OAuth で接続」はデバイスフローで、
   表示されたコードをコピーし、リンク先に貼って承認を待つ。以後の clone と push で
   トークンを聞かれることはない

エージェントと GitHub の接続はホームに保存される。ワークスペースを止めても、別の端末から
ログインし直しても繰り返さなくてよい。

ようこそカードは「あとで」で閉じられる。同じチェックリストはアカウントメニューの
「はじめかたガイド」から開き直せる。

## リポジトリを持ってくる

左ペイン「リポジトリ」の「追加」で、種類を Git のままにする。「接続から選ぶ」で
リポジトリとブランチを選び、「クローン」を押す。接続した GitHub の一覧に無いものは
「URL 手入力」で clone URL を貼る。clone 先は `~/repos` の下になる。

ワークスペース操作バーの「＋ はじめる」→「新しいリポジトリをクローン…」を使うと、clone から
セッションの起動までを続けて行える。

submodule と Git LFS の実体は clone 時に自動で取得される。大きな submodule は取得が
間に合わないまま作業が始まることがあり、その場合は通知センターに出る。

## ワークスペースの環境

ワークスペースの中では root も `sudo` も `apt` も Docker も使えない。必要なツールは
ユーザー領域に入れる（`pip install --user` で入れたものはホームに残る）。

⚙設定 →「ツールチェーン」タブで、タイムゾーン・Node.js・Java の版を選べる。Java は
まだ入っていない版も一覧に出て、その場でインストールできる。

ホストのメモリは共有で、セッションごとにメモリを使う。重いビルドは1つずつ走らせ、
dev サーバーや watcher を放置しない。Node 系のビルドでは必要なコマンドだけ
`NODE_OPTIONS=--max-old-space-size=2048` のようにヒープを上げ、Gradle は使い終わったら
`./gradlew --stop` で止める。

## 一日の終わり

ワークスペース操作バーでワークスペースを止める。止めても次のものは残る。

- clone したリポジトリと、その中のコミット前の変更
- セッションの一覧。停止中として残り、次に起動したときにクリックで再開できる
- エージェントと GitHub の接続

push していない変更はワークスペースの中にしか無い。区切りごとに push しておく。

止め忘れても、しばらく操作が無ければ自動で止まる。止まっている間も左ペインの
セッション一覧は見えるが、中身は操作できない。

Console が更新されると「更新」ボタンつきの通知が出る。これはブラウザを読み込み直すだけで、
実行中のセッションは止まらない。電源ボタンの横に「要再起動」バッジが出たときは、
ワークスペースを新しい版で起動し直す必要がある。押すと停止と起動を行い、実行中の
セッションは停止中になる。急ぐ必要はない。

## 環境が壊れたとき

⚙設定 →「危険な操作」タブに2段階のリセットがある。どちらも未コミットの変更は消えるので、
先に push しておく。

| 操作 | 消えるもの | 残るもの |
|---|---|---|
| ワークスペースを作り直す | 実行中のセッションと `~/repos` | ホームの残り（接続・`~/.local`・設定・キャッシュ） |
| ホームを掃除する | 接続以外のホーム全体 | エージェントと GitHub の接続 |

まず作り直しを試し、`~/.local` やキャッシュが原因で直らないときだけ掃除を使う。

症状別の対処は本家の `guide/member/11-troubleshooting.ja.md` にある。claude を選ぶと
ログイン画面が出る、セッションが再開できない、clone に失敗する、といった初日に出やすい
症状もここで引ける。
