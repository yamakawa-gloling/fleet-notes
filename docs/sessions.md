# セッションを回す

本家の `guide/member/02-sessions.ja.md`・`07-chat-memo.ja.md`・`08-organising.ja.md`・
`09-collaboration.ja.md` から、日々の作業で使う操作を抜き出した。

セッションは、エージェントに任せる1つの仕事について、会話・作業フォルダ・実行状態を
まとめた単位である。左ペインでは作業フォルダのリポジトリの下に並ぶ。

## 起動する

リポジトリの行の「起動」か、ワークスペース操作バーの「＋ はじめる」でリポジトリを選ぶと、
「作業を始める」が開く。ここでエージェント・モデル・推論の強さ・場所・最初のプロンプトを
選ぶ。「起動」の右の ▾ からは、既定の設定のまま種類だけ選んで起動できる。

「場所」は次の2つから選ぶ。

- **新しい worktree**（既定）：そのセッション専用の作業コピーを切り出す。基点ブランチと
  ブランチ名を指定でき、ブランチ名が空なら `temp/…` という暫定名になる。作った直後に
  その worktree だけを `origin/<基点ブランチ>` へ fast-forward するので、古い clone から
  切っても origin の先端から始まる
- **このコピーで直接**：clone した作業コピーでそのまま作業する

同じリポジトリで複数のセッションを並べるときは、セッションごとに worktree を分ける。
作業コピーを共有すると、片方のブランチ切り替えがもう片方の編集とぶつかる。

「詳細」の「作業ディレクトリ」で、エージェントを起動するフォルダをリポジトリの下に絞れる。
monorepo で一部のディレクトリだけを触るときに使う。

最初のプロンプト欄の「テンプレート」には、自分用のテンプレートと最近のプロンプトのほか、
リポジトリにコミットされた `.agent-fleet/launch-prompts.md` の項目（`## 見出し` ごとに1件）が
並ぶ。チームで使う定型の依頼はこのファイルに置けば、clone した全員に出る。
`{{repo}}`・`{{branch}}`・`{{path}}` は起動した行の値に置き換わる。

claude は端末（CLI）で動く。codex などは既定でマネージド実行になり、端末を持たずに
チャット画面だけで操作する。

## 応答する

エージェントの質問・プラン・許可の要求は、チャット画面にカードとして届き、その場で答えられる。
左ペインの各行の末尾に状態が出る。

| 状態 | 意味 |
|---|---|
| 進行中… | 作業中 |
| 質問あり／プランあり／許可待ち | こちらの返事を待っている |
| 入力待ち | 手が空いて次の指示を待っている |
| 制限解除待ち | 利用上限で止まっている。時刻が付いていれば、その頃に自動で再開する |
| 停止中 | 止まっている。クリックで開いて再開できる |
| フォルダ無し — 再開不可 | 起動時の作業フォルダが消えて再開できない |

見ていない間に入力待ちになったり質問が来たりすると、ブラウザ通知が出る。未読の通知がある
セッションには赤いドットが付く。

チャット画面の上部の「コンテキスト」ゲージで、今の会話が使っているトークンと上限が分かる。
長い作業で文脈が薄くなったと感じたら、ここを見る。

## 止める・片付ける

操作はセッションの行の ⋯ メニューにある。迷ったら「停止する」を選ぶ。

| 操作 | 結果 | 戻し方 |
|---|---|---|
| 停止する | 停止中として一覧に残る | クリックして再開 |
| アーカイブする | 会話を残して一覧から隠す | アーカイブ一覧から復帰 |
| 作り直す | 今の会話をアーカイブし、同じ場所で新しい会話を始める | 古い会話はアーカイブから復帰 |
| 削除する（shell のみ） | ごみ箱へ移す | 掃除のごみ箱から復元 |

停止中のまま7日経ったセッションは自動でアーカイブへ移る。アーカイブから自動で消えることは無い。

「ターン終了後に停止する」は、今のターンが終わったところで止める予約である。セッションに
「終わったら停止して」と頼んでも同じ予約が入る。新しい指示を送ると予約は解除される。
逆に、長く走らせたいセッションは「自動停止しない」で指定した時間だけ自動停止から外せる。

散らかってきたら、「リポジトリ」見出しのゴミ箱アイコンから掃除を開く。候補には安全度が付く。

| 安全度 | 意味 |
|---|---|
| 安全 | マージ済みでクリーンなど、消しても失うものが無い |
| 要確認 | 停止中のセッションや、クリーンだが未マージの worktree。中身を見てから決める |
| 保持 | 稼働中、未コミット・未 push、削除ロック中。掃除の対象にならない |

消したセッション・ブランチ・worktree はごみ箱へ入り、「ごみ箱（復元）」タブから戻せる。
worktree は未コミットの変更も記録されるが、`.gitignore` の対象（`node_modules`・`.env` など）は
戻らない。消えてはいけないセッションには ⋯ メニューで削除ロックをかけておく。

1つの仕事ぶん（親の worktree とそこから起こした子の worktree）だけを片付けるときは、行を
右クリックして「作業コピーを削除」を選ぶ。セッションのアーカイブと worktree の削除が1回で済む。

worktree を消したあとでセッションを再開したくなったら、アーカイブ一覧の
「作業コピーを作り直す」で同じパスに worktree を戻せる。

## 費用の上限を付ける

起動ダイアログの「詳細設定 → 予算（米ドル）」か、⋯ メニューの「予算…」で、セッションに予算を
付けられる。推定費用が予算に達すると、そのターンが終わったところで止まる。推定は会話記録から
定価で見積もった値で、サブスクリプションでサインインしている場合は API 換算の値になる。
請求額ではない。

⚙設定 →「エージェント」の「使わないモデル」に入れたモデルは、起動ダイアログやアシスタントの
選択肢から消える。誤選択を防ぐ設定であり、端末で `/model` を打つ操作までは止められない。

## 並行して回す

**引き継ぎ（handoff）。** ⋯ メニューの「別のエージェントへ引き継ぐ…」で、要点・未完了の作業・
変更したファイルをまとめた引き継ぎ案を作り、同意すると新しいセッションを起こす。会話を
そのまま複製したいときは、チャット画面で過去の自分の発言から「ここから分岐」を使う。

**フリート・オペレーター。** 左ペインの「アシスタント」にいる、セッションを指揮する役の
アシスタントである。チャットで頼むと、セッションの状態や出力を読み、指示を送り、worktree を
切って新しいセッションを起こす。自分ではファイルを編集しない。指示したセッションが
入力待ちになるか異常終了すると、オペレーターの会話に報告が届く。並行して実装させるのは
2〜3本までを目安にする。

**定時実行。** オペレーターに「毎平日9時に昨日の変更をレビューして」のように頼むと
登録される。止まっているワークスペースも起こして実行する。一覧・履歴・編集は左ペインの
「スケジュール」にある。

**子セッション。** ⚙設定 →「エージェント」→「セッションからのセッション起動」をオンにすると、
セッションが自分で別のセッションを起こして仕事を渡せる。既定はオフである。

## 共有する

⋯ メニューの「共有する」で、同じテナントのメンバーに会話を見せられる。対象はセッション1本・
worktree 1つ・作業コピーとその配下全体から選び、権限は「閲覧のみ」か「提案可」を選ぶ。
「提案可」でも、相手の送った内容は所有者が承認するまでエージェントに届かない。

共有を解除しても、相手が保存したコピーは回収できない。共有する前に、会話に秘密情報が
写っていないかを確かめる。

## 自分の働き方を一度だけ書く

⚙設定 →「エージェントへの指示」に書いた文章は、新しく起動するエージェントの指示に加わる。
報告の言語や確認を取ってほしい場面など、毎回プロンプトに書いていることをここへ移す。
リポジトリにはコミットされず、本人のセッションにだけ効く。チームで揃える指示は、これまでどおり
リポジトリの `CLAUDE.md` や `AGENTS.md` に書く。秘密は書かない。
